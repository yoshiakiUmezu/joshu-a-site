# 価格・収益判断ルール

Last updated: 2026-10-06

## 目的

価格を「なんとなく」で決めず、Pro費用回収と月5万円純利益への距離を即座に判断できるようにする。

## 利益の基本式

```
1件あたり純利益
= 販売価格
- プラットフォーム/決済手数料
- 返金・税等の直接変動費
- 1販売あたりで発生する追加原価
```

```
月間純利益
= 1件あたり純利益 × 月間販売数
- 製品固有の月額固定費
- 販売維持のための外注/有料サービス等
```

ChatGPT Pro 100は「事業全体の設備費」として別途評価する。個別商品の採算判定では、まず商品単体の直接利益を出し、その後ポートフォリオ全体でPro費用を吸収できるかを見る。

## 収益ステージ

### Stage 1 — Pro余剰
目標:
- Pro 100費用を支払っても毎月余剰が残る
- 暫定事業目標: 月2.5〜3万円程度以上の純利益を一つの目安とする

### Stage 2 — 月5万円純利益
- Pro費用を吸収した上で十分な余剰
- 最初の安定目標

### Stage 3 — 月10万円以上
- 上位Proや追加投資を検討できる水準
- 追加固定費はROIで判断

## 販売数の逆算

各商品について、価格候補ごとに次を計算する。

```
必要販売数 = 目標月間純利益 / 1件あたり純利益
```

端数は必ず切り上げる。

例として、1件あたり純利益が:
- 500円なら月3万円に60件、月5万円に100件
- 1,000円なら月3万円に30件、月5万円に50件
- 2,000円なら月3万円に15件、月5万円に25件
- 3,000円なら月3万円に10件、月5万円に17件
- 5,000円なら月3万円に6件、月5万円に10件

これは価格推奨ではなく、販売必要量を直感的に見るための基準。

## 価格決定の順番

1. **顧客価値**
   - 何分/何時間を節約するか
   - 何の面倒を消すか
   - ゲームなら体験量・独自性・完成度

2. **代替価格**
   - 同じ問題を解く競合
   - 無料代替
   - ストア内の価格帯

3. **必要販売量**
   - その価格でStage 1 / 2に何件必要か
   - Discovery規模に対して現実的か

4. **人手コスト**
   - 問い合わせ
   - 更新
   - ストア審査
   - 返金
   - 手動運用

5. **価格摩擦**
   - 衝動買いできる価格か
   - 比較検討が必要な価格か
   - デモ/無料版が必要か

## 悲観・基準・楽観シナリオ

製品公開前に販売数を3ケースで置く。

- **悲観:** Discoveryが弱い、初期認知ほぼなし
- **基準:** 想定チャネルで通常の初期流入が得られる
- **楽観:** 外部Discoveryや口コミが機能する

ルール:
- 悲観ケースが赤字なら「自動的に中止」ではない
- ただし赤字継続に上限を持たせる
- 基準ケースでも直接利益が出ない商品は、戦略商品である理由が必要
- 楽観ケースだけで成立する商品は優先度を下げる

## 公開後の判断

### 流入がない
価格を下げない。Discovery改善が先。

### 流入はあるがCTAが弱い
価値説明、対象ユーザー、スクリーンショット、信頼要素を改善。

### CTAは押されるが購入されない
価格、ストア導線、提供条件、決済摩擦を確認。

### 売れるがサポート負荷が高い
価格を上げる、FAQ/自動サポートを強化、製品自体を修正。

## 値下げルール

次を確認するまで値下げしない。

- 十分な製品ページ流入がある
- CTAまで到達している
- 提供先に技術的障害がない
- 価値説明が明確
- 競合比較で価格が明らかに不整合

「売れない = 高い」とは判断しない。

## 販売停止/保留判断

次のいずれかが続く場合、追加開発より停止/保留を検討する。

- 継続人手が利益を上回る
- 有料外部サービス依存で利益が残らない
- 重大な法務/権利/セキュリティ負担
- 販売チャネル要件が個人運用に対して過大
- 十分な流入を作っても購入意向が見えない
