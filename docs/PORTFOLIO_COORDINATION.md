# 助手A — GitHub経由の横断進捗集約・統括運用

Status: PROPOSED / 最小運用開始準備
Updated: 2026-10-11
Owner: 事業・販促統括窓
Scope: A.I. TERMINAL、公式サイト・販促、無料知育コンテンツ、X運用、Meguribi

## 目的と非目標

**ユーザーが専門窓の回答を統括窓へコピーする作業をなくす。**
各専門窓が既存のGitHub正本（PR/Issue/MD/CI）に作業の証拠を残し、統括窓は自分で収集、矛盾を調査し、案件横断の優先順位を判断する。

ChatGPTの別会話窓同士に、メッセージ配信・自動通知・自動会話再開を行う機能ではない。
新しい有料API、外部DB、Webhook、GPT間直接通信、GitHubの追加権限は導入しない。

進行中のPRにだけある更新は、`main`と**両方**確認し、`main`に反映済みとは扱わない。PR番号・HEAD・Draft/mergedと確認日時を残す。
別の案件が追加されたときだけこの一覧を更新する。実在しないリポジトリ名を推測して収集対象に加えない。

## 各窓の最低限の記録契約

新たな週報を全員に書かせない。既存文書とPRを利用する。

1. 完了した作業はPR・CI・実機確認などの**検証証拠**とともに記録する。
2. 進行中の作業は、担当・依存・次の具体的な実行条件を記録する。
3. 阻害要因は、原因が確定/仮説/未確認のどれかを示す。
4. 人間の承認が必要な操作は、**対象・影響・理由・承認待ち**を明示する。
5. 公開・マージ・配信の完了は実際の本番結果やreadbackで確認する。Draft PRだけでは完了としない。
6. 既存ドキュメントの担当範囲を守り、他窓の管理ファイルを勝手に編集しない。
7. 他担当へ新しい作業が必要なときはGitHub Issueまたは担当するPR/MDに「依存/依頼」として残せる。ただし**書き込んだだけで他のChatGPT窓が受信・着手するとは限らない**。

統括窓が一回の問い合わせで読むべき基礎出力は「完了／進行中／ブロッカー／要承認／次の作業／情報の鮮度」。追加の作業日報やコミット数ノルマは禁止。

## 自動収集・報告頻度

- **通常時**：ユーザーがこの統括窓で「横断進捗を確認」と言えば、その場でGitHub上の最新正本、PR、CI等を読む。ユーザーに他窓からのコピペを要求しない。
- **定期時**：既存のA.I. TERMINAL 7:00・16:00・22:00 JSTレポートを再利用する。7/16時はTerminal集中、**22時だけ短い全案件横断サマリーを追加**。同時刻に重複する新規通知タスクは作らない。
- **Meguribi**：既存の週次報告と重複する深掘りはしない。統括22時欄は主な変化だけ。存在する週次レポートに実績がなければGitHubを直接読む。
- **10/18点P投稿評価**：既存の一回限り評価タスクをそのまま利用し、重複作成しない。
- **重要な変化**：保護操作の承認要求など、ユーザーが別窓や通常のChatGPT画面で確認する必要がある場合は、「待ち」を明記。GitHubだけで本人へリアルタイムPushできるとは主張しない。

## 横断判断フォーマット

表または短い段落で、案件ごとに次を記載する。

- `CONFIRMED`：GitHubや実機/本番の確認できる証拠がある
- `REPORTED`：本人/担当窓からの報告はあるが独立検証は未完了
- `UNKNOWN`：ソースにアクセスできない、情報不足、または古い
- `BLOCKED`：前提条件が未達で進められない
- `APPROVAL_REQUIRED`：ユーザー承認が必要な対象

「実装済み」と「実運用で再現確認済み」「本番でユーザーが利用できる」を混同しない。

優先度は、(a) Terminalの自走開発受入試験、(b) 初の有料商品候補/初売上への距離、(c) ユーザーの人手削減、(d) 依存解消で動く作業数、(e) リスクと維持費で評価。新機能の数やコミット数で評価しない。

## 今回の初期対象・注意

- Terminalの主な受入候補は `0.5 MEMORY SHOT`。実際の受入状態は毎回GitHubで更新確認し、既に合格したものを未完了としない。
- 無料知育は現時点で10件がGitHubに存在する。ただし公開後の訪問・操作実績はアクセス分析の確定値が必要。
- Xの点Pデモ: https://x.com/JoshuA_criate/status/2109180511898005591 。内容・インサイトはアクセスできた根拠で判断。10/18効果評価は別の既存タスクで予定。
- Cloudflareダッシュボード/Xの非公開インサイト/PC上のdots動作・実機UIはGitHubだけでは確認できないことがある。「見えない」「未確認」と区別して報告する。
- 無関係な依存作業まで一律停止せず、保護された操作にだけ人間承認を求める。

## 安全・変更管理

この文書は事業統括の運用ルールであり、Terminalの実装仕様や販売判定エンジンではない。変更は事業・販促統括窓の担当。
ドキュメントの編集は最新mainと進行中PRを確認し、専用作業ブランチ → Draft PR で記録する。mainへの無承認直push、無承認マージ、強制pushはしない。

このドキュメントの作成は、各別窓への命令が自動的に届いたことや、定期タスクが作成/変更されたことの証明ではない。タスク設定と結果は別途確認する。
