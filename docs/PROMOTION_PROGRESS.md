## 検索可視性ベースライン

2026-10-06時点の一般ウェブ検索では、`site:joshu-a.com` や「助手A 個人開発 ソフトウェア ゲーム」などで joshu-a.com の有意な検索結果を確認できなかった。

これは新規サイトでは不自然ではなく、現時点では技術的SEOの追加量産よりも、
1. Search Console / Bingへの登録
2. 実製品という一次情報の追加
3. 外部チャネルからの実リンク獲得
を優先する。

検索結果がないことだけを理由に薄いSEO記事を量産しない。

## 自動で進めてよい販促作業

人間判断や外部アカウント操作を必要としない範囲では、以下を自動で進めてよい。

- サイトの技術監査
- SEO / structured data / sitemap / robots の整合確認
- 製品ページテンプレート改善
- 公開チェックの自動化
- CTA / UTM / URL規則の検証
- 外部チャネル用テンプレートの準備
- 競合 / 販売チャネル / 手数料 /価格の公開情報調査
- 公開後の検索可視性確認
- 実データに基づく導線改善案

## 人間判断が必要な販促作業

- 実際の価格確定
- ストア契約・有料サービス契約
- 外部アカウントへのログイン / 本人確認
- Search Console / Bing等の所有権確認

- 法務 / 税務 / 契約判断
- 実製品の公開可否

## 将来設計テーマ — 助手A固有の勝ち筋

一般的なSEO・CTA・価格最適化だけで競争しないため、実製品の公開後に「助手A固有の市場学習ループ」を設計する。

検討対象:
- どの製品特性にユーザーが反応したか
- どの流入元が購入につながったか
- 価格変更で反応がどう変わったか
- どの検索語・訴求・デモが強かったか
- どの販売チャネルで人手と利益のバランスが良かったか
- 製品Aの販売データを製品Bの要件・価格・販促へどう戻すか
- 一般AIの市場知識と助手A固有データをどう分離・統合するか
- A.I. TERMINAL Commercialization Pipelineへどの形で学習結果を返すか

原則:
- 実データがない段階で架空の最適化モデルを作り込まない。
- 最初の1〜2製品から得られた一次データを起点に設計する。
- 一般的なベストプラクティスは衛生要件として維持し、競争優位そのものとはみなさない。
