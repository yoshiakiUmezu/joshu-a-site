# 販売後の診断・改善ルール

Last updated: 2026-10-06

## 目的

製品公開後に「売れない」を一括りにせず、どこで詰まっているかを短時間で特定し、次の1手を機械的に決める。

## 基本ファネル

Discovery
→ 製品ページ到達
→ CTAクリック
→ ストア/配布先到達
→ 購入/DL
→ 継続利用
→ サポート/再訪

## 症状別の優先診断

### 1. 流入がない
見るもの:
- 検索表示
- 外部チャネル露出
- ディープリンク
- インデックス状況

やること:
- Discoveryチャネルを増やす/改善する
- 検索登録・sitemap・外部リンク確認
- 製品に合う itch.io / X / note / Steam 等を再評価

やらないこと:
- すぐ値下げ
- 製品機能を増やす
- CTA文言だけ変える

### 2. 流入はあるがCTAが押されない
見るもの:
- 一文価値
- 対象ユーザー
- スクリーンショット/動画
- 価格の見え方
- 信頼要素
- 対応OS/提供条件

やること:
- 価値説明を短く明確にする
- 対象ユーザーを狭くする
- デモを改善する
- FAQを追加する

### 3. CTAは押されるが購入/DLされない
見るもの:
- ストアページ
- 価格
- 決済
- ログイン/審査/地域制限
- ダウンロード手順
- 不明確な対応環境

やること:
- 購入導線の摩擦を減らす
- 価格と競合を再比較する
- ストア記述を公式サイトと一致させる

### 4. 購入されるが継続利用されない
見るもの:
- 初回起動
- 導入手順
- 期待値とのズレ
- バグ
- 初期体験

やること:
- オンボーディング改善
- 初回価値到達までの時間短縮
- 不具合修正

### 5. 売れるが人手負担が重い
見るもの:
- 問い合わせ件数
- FAQで防げる内容か
- 不具合率
- 手動運用
- 返金/更新対応

やること:
- 自動サポート
- FAQ/トラブルシュート強化
- 製品内セルフ診断
- 価格見直し
- 販売チャネル変更

## 改善の順番

1. 計測が正しいか
2. Discovery
3. 製品ページ
4. CTA
5. ストア/購入導線
6. 価格
7. 製品機能

「売れないから機能追加」は最後。

## 72時間レビュー

公開72時間後に最低限:
- 流入
- CTA
- 購入/DL
- 問い合わせ
- 不具合
を確認する。

データ量が少ない場合は結論を急がない。

## 7日レビュー

- 流入元別
- CTA率
- 購入/DL率
- サポート負担
- 価格反応
を見て、次の改善を1つだけ選ぶ。

## 30日レビュー

- 月間純利益
- 継続人手
- 改善後の変化
- 次の製品へ横展開できる学び
を整理する。

判定:
- 継続
- 改善継続
- 値上げ/値下げテスト
- チャネル変更
- 保守モード
- 販売停止

## 原則

- 一度に複数箇所を変えすぎない
- 改善前後の差が分かるようにする
- 売上だけでなく人手もコストとして扱う
- 十分な流入なしに価格を断定しない
- 口コミ/一時バズだけを通常値として扱わない
