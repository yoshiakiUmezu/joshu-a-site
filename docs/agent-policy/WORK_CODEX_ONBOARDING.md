# Work向け：新しい開発案件の自動ループ導入依頼

この依頼は、助手A標準規約 [WORK_CODEX_REVIEW_LOOP.md](WORK_CODEX_REVIEW_LOOP.md) の導入手順。**毎工程の初期設定を不要にする**ことが目的。初回に設定した巡回をPASS後も維持する。

## Workへ渡す共通指示（案件に応じてリポジトリを指定）

> 今回の対象リポジトリについて、`docs/agent-policy/WORK_CODEX_REVIEW_LOOP.md` の標準ルールに従い、自動化を**初回1回だけ**設定してください。
>
> 1. GitHubの仕様・AGENTS.md・既存PRを確認。承認条件は変更せず、指示一覧と未処理タスクの入口を用意する。**別の進捗正本や並列キューを作らない**。
> 2. 既存Codexスレッドがあるならそれを優先。なければ対象プロジェクト専用のスレッドを作成できるか確認。可能なら同じスレッドに残るThread automationを作成し、**指示一覧**を巡回させる。PASS後も削除しない。できない場合は設定済みと偽らない。
> 3. 当該リポジトリのPR ready_for_reviewと更新イベントに対応するWork検収タスクを初回設定し、指示IDを確認してレビューする。必要な権限・イベント登録でユーザー操作が必要な場合だけ止め、最小の手順を1回だけ伝える。
> 4. 空の指示一覧で勝手に製造させない。最初の承認済みタスクで、**Codex同じスレッドによる検知→PR→Work自動検収→同PR更新の再検収**を検証する。元ログ等で確認できない項目は未確認とする。
> 5. 品質PASS後は次案を1件提示するが、ユーザー承認前に次タスクを投入しない。A.I. TERMINAL・dots・研究／運用専用リポジトリは除外。API課金、Actions、公開、デプロイは別承認とする。

**自動化の限界:** ChatGPT ChatのGitHub接続からは他のCodex窓のThread automationを直接生成する操作は公開されていない。Workの画面操作で対応できる場合はWorkがまとめて実施し、できなければ「その案件に必要な最初の1操作」のみをユーザーに報告する。これは技術的制約であり、文書登録だけで完全無人導入を保証しない。
