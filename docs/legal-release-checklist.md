# 製品公開時の法務・プライバシー確認

助手Aからソフトウェアやゲームを公開するとき、製品の配布方法、販売主体、データの流れ、同梱物を確定してから必要な表示を選ぶための内部チェックリスト。無料・有料、ソフトウェア・ゲームのどちらにも使う。法律上の結論を自動で決める文書ではない。各ストアの規約と日本の公式情報は、実際の公開時点で再確認する。

## 現在の joshu-a.com

2026-10-06 時点で実製品と製品ページはなく、サイトの問い合わせ先は `contact@joshu-a.com`。提供された現状とリポジトリ上の構成では、フォーム、アカウント、決済、Analytics、広告、追跡 Cookie は導入されていない。問い合わせメールには差出人のアドレスや本文が含まれ得るため、「個人情報を一切扱わない」とは表現しない。ホスティング事業者のアクセスログ等は、実際の設定と契約を公開前に確認する。

**現時点の判断:** サイト全体の利用規約、独立したプライバシー、特定商取引法、返品・返金、ライセンスの各ページを P0/P1 として追加する必要は確認できない。空の法務ページや架空の販売者情報は公開しない。今は既存のメール窓口を維持し、問い合わせ内容を返信・対応以外に使う運用を始める場合や収集方法を増やす場合に、利用目的の説明方法を見直す。[個人情報保護委員会のガイドライン](https://www.ppc.go.jp/personalinfo/legal/guidelines_tsusoku/)は、個人情報の取得時の利用目的の通知・公表と、入力画面等で直接取得する場合の明示を説明している。

以下の「常に必要」は**製品公開の内部確認として常に実施**する意味であり、独立した法務ページの法的義務を意味しない。「条件付き」は該当機能・販売方式・ストア規約で必要性が生じるもの。「通常不要」は現状や単純な無料配布では独立した表示を先に作らないもの。

## 法務要素の分類

| 要素 | 区分 | 公開前の判定 |
| --- | --- | --- |
| 利用規約 | 条件付き | アカウント、クラウド、投稿・共有、独自の利用制限、直接販売の契約条件があるとき、製品に合う条件を作る。単純なオフライン製品にサイト共通の空規約を作らない。 |
| プライバシーポリシー | 条件付き | 個人・端末データ、フォーム、SDK、外部 API 等を扱う場合に実際の処理を記載。Google Play ではデータ収集なしでもアプリのポリシー URL と Data safety の申告が必要。[Google Play 公式](https://support.google.com/googleplay/android-developer/answer/10787469) |
| 特定商取引法に基づく表示 | 条件付き | 助手Aが通信販売の販売業者になる場合、表示事項と広告・申込画面を公式情報で確認。外部ストア販売でも販売主体とサイトの広告の役割を確認。[消費者庁](https://www.no-trouble.caa.go.jp/what/mailorder/) |
| 返品・返金条件 | 条件付き | 有料なら購入前に適用される条件と申請先を明確にする。外部ストアの規則を勝手に上書きしない。直接販売は特商法の表示事項と決済・提供条件を確認。[消費者庁](https://www.no-trouble.caa.go.jp/what/mailorder/) |
| 製品の利用ライセンス | 条件付き | 再配布、改変、商用利用等に独自の条件を設ける場合は製品に即した条件を示す。ソースを公開する場合は公開範囲とライセンスを確定する。 |
| OSS ライセンスと第三者権利 | 常に必要 | 全ての配布物・素材・SDKを棚卸しし、該当する許諾、同梱、表示、ソース提供条件を満たす。第三者が一切なければ専用ページは不要。 |
| 著作権表記 | 条件付き | 自作物の権利者と第三者の attribution を正しく表示する。`©` だけの独立ページは通常不要で、表記の有無だけで権利が生まれるわけではない。 |
| 年齢関連表記 | 条件付き | ゲーム内容、対象年齢、成人向け要素、子ども向け機能、ストアの審査・レーティングを確認。[Steam Content Survey](https://partner.steamgames.com/doc/gettingstarted/contentsurvey)、[Google Play 年齢区分](https://support.google.com/googleplay/android-developer/answer/9859655) |
| 問い合わせ窓口 | 常に必要 | 製品ページまたは配布先から届く実際の連絡先を確保し、受信・返信を確認する。法定の連絡方法は販売方式ごとに別途確認。 |
| 不具合報告窓口 | 条件付き | 公開製品では連絡経路を示す。独立メール・フォームは不要なら作らず、既存窓口で受ける。 |
| 外部ストア規約との関係 | 条件付き | ストアを使う場合、販売主体、年齢・AI・データ申告、返金、サポートの責任分担を確認する。 |
| Cookie / Analytics 表記 | 条件付き | 導入する技術、送信先、目的、保存期間、オプトアウト・同意要件を確認。Cookie を使わない段階の定型バナーは不要。 |
| crash reporting / telemetry の説明 | 条件付き | 端末識別子、ログ、操作履歴、送信頻度、送信先、保持期間、停止方法を実装どおり説明する。 |
| 広告 SDK の説明 | 条件付き | SDK の収集・第三者送信、識別子、同意や子ども向け制限、ストア申告を確認する。 |
| AI 利用の表示 | 条件付き | 外部 AI へユーザー入力を送る場合は送信内容・処理先・保存等を説明。ストアが生成 AI や生成素材の申告を求める場合も対応。[Steam Content Survey](https://partner.steamgames.com/doc/gettingstarted/contentsurvey)、[Google Play の生成 AI 申告](https://support.google.com/googleplay/android-developer/answer/17262077) |

## 製品タイプ別の分岐表

各行は重ねて適用する。例えば「無料ゲーム + crash reporting + Google Play」なら A、F、ストア共通確認の全てを確認する。ここでの「文書」は独立ページに限らず、製品内表示、ストア欄、ライセンス同梱物を含む。

| 条件 | 公開前に必要な文書・表示 | 確認のゲート |
| --- | --- | --- |
| A. 無料製品・個人情報収集なし | 実際の利用・配布条件、該当する第三者ライセンス、サポート先。サイト共通の規約・特商法ページは自動追加しない。 | 通信・SDK・ホスティング・ストア申告も含めて「収集なし」が正しいか確認。無料ゲームは内容に応じて年齢表示を確認。 |
| B. 有料製品・外部ストア | 実売価格、販売主体、返金条件の参照先、製品利用条件、ストアが要求する表示。 | itch.io の決済方式、Steam / Google Play 等の販売・返金・年齢・プライバシー規則を個別に確認。サイトが販売広告に当たる場合の表示も要確認。 |
| C. 自サイト直接販売 | 特商法の必要表示、価格・追加費用、支払・引渡時期、解約・返金条件、申込最終確認、連絡先、必要なプライバシー説明。 | **販売開始前の停止ゲート**。実際の販売主体、氏名・住所・電話番号の扱い、販売画面、決済事業者の契約・データ処理を公式情報と必要なら専門家で確認。 |
| D. ユーザーデータ収集あり | データ種類・利用目的・提供先・保持・削除・連絡先を反映したプライバシー説明。 | 収集開始前に実データフローと同意・通知・安全管理・越境移転の要否を確認。 |
| E. 広告あり | 広告 SDK と識別子・送信先の説明、必要な同意・ストア申告。 | SDK 実装、対象年齢、第三者送信、地域別要件を確認。 |
| F. crash reporting / telemetry あり | 収集フィールドと送信先・目的・保持・停止方法の説明。 | クラッシュ本文にファイルパスや入力内容等が混ざるか、既定送信か任意送信かを実測。 |
| G. アカウント機能あり | アカウント条件、個人情報の取扱い、削除・問い合わせ方法。 | 認証、復旧、退会、保持データと削除手段を確認。Google Play 配布時はアカウント削除要件も確認。[Google Play 公式](https://support.google.com/googleplay/android-developer/answer/13327111) |
| H. cloud sync あり | 同期対象、保存先、共有・削除・バックアップ、障害時の取扱い、利用条件。 | 保存先事業者、地域、復元・消去、通信保護、データ流出時の対応を確認。 |
| I. AI 機能あり | 入力・出力の外部送信、保存、モデル提供元、利用制限、生成結果の注意を実態に合わせて説明。 | ユーザー情報の送信、生成物の権利、誤情報・有害出力対策、ストア申告を確認。ローカル AI のみなら外部送信があるように書かない。 |

**ストア共通確認:** Google Play ではデータ収集がなくてもプライバシーポリシーと Data safety 申告が必要。年齢区分も申告する。Steam は発売前の Content Survey で成人向け要素や生成 AI の利用を確認する。各ストアの要求は公開直前に公式ページで再確認する。

## 販売方式と特定商取引法

通信販売の広告では価格、支払方法・時期、引渡時期、申込みの撤回・解除、販売業者情報、ソフトウェアの動作環境等が論点になる。個人が反復継続して営利販売する場合も対象となり得る。[消費者庁の通信販売案内](https://www.no-trouble.caa.go.jp/what/mailorder/)を参照。氏名・住所・電話番号を推測で書かず、省略や代替住所の可否は[消費者庁の通信販売広告 Q&A](https://www.no-trouble.caa.go.jp/qa/advertising.html-2)と実際の販売形態に照らして確認する。請求時の遅滞ない提供など、省略の条件を満たせるかも確認する。

| 方式 | 判断 |
| --- | --- |
| 外部ストアが販売主体 | ストアの契約と購入画面で実際の販売主体を確定する。ストアの表記・返金窓口を案内し、助手Aのサイトの広告表示が別途何を要するかは要確認。 |
| 助手Aが直接販売主体 | 上記の表示事項と申込最終確認を公開前に確定する。単なる決済代行の利用だけで販売主体が移るとは扱わない。 |
| 無料配布 | 対価を受けない配布なら有料通信販売の表示を機械的に足さない。別の有料オプションや購入誘導があれば再判定。 |
| 寄付・任意価格 | 無料選択肢があっても金銭の授受がある。対価性、販売主体、寄付の実態、返金・税務を要確認。itch.io は「Direct to you」と「Collected by itch.io」で merchant of record が異なる。[itch.io 公式](https://itch.io/docs/creators/payments) |
| 買い切り | 提供範囲、更新・サポート、支払・引渡時期、返品・返金条件を購入前に示す。 |
| 将来のサブスク | 期間、更新・解約方法、継続課金、請求時期、最終確認画面を追加で確認。開始前に公式情報・専門家確認候補。 |

通信販売のクーリング・オフ、返品特約、契約不適合時の権利を一つの「返金不可」で片付けない。デジタル製品に適用する条件は販売開始前に確認する。[消費者庁の通信販売案内](https://www.no-trouble.caa.go.jp/what/mailorder/)。Steam は[Steam の返金規則](https://store.steampowered.com/steam_refunds/)、itch.io は[決済方式](https://itch.io/docs/creators/payments)と[返金条項](https://itch.io/docs/legal/terms)を参照し、自サイトで矛盾する約束をしない。

## 問い合わせ設計

現段階は `contact@joshu-a.com` の一本で、一般問い合わせ、不具合、購入関連、プライバシー、権利侵害の連絡を受ける。目的ごとにアドレスを増やすのは、実際の件数や担当分離が必要になったとき。購入後の返金処理は販売ストアの窓口が優先される場合があるため、製品公開時にその導線を明記する。

公開前にメールの受信・返信と迷惑メール振り分けを実操作で確認する。不具合報告は製品名、版、環境、再現手順を任意で案内し、氏名・住所・電話番号、全ログ、機密ファイルの提出を一律に要求しない。ログやスクリーンショットを送る場合は個人情報を消せるように案内する。問い合わせ記録の利用目的、保持・削除、委託先は実運用が決まった時点で確認する。

## 公開時ゲートと既存テンプレート

1. 製品の無料・有料、買い切り・任意価格・サブスク、販売主体、配布先を確定する。
2. 本表の A〜I を重ね、機能・SDK・外部通信と年齢・AI の申告事項を実装と照合する。
3. 権利・ライセンス台帳を確認し、必要な notice やクレジットを配布物に含める。
4. 有料なら価格、支払・提供・返金の条件と窓口を購入前に確認する。直接販売なら特商法と最終確認画面が確定するまで公開しない。
5. 必要な利用条件、プライバシー、ライセンス、返金条件、販売者情報、サポートへの**実在する**リンクだけを製品ページ・ストア欄・製品内に置く。どこに置くべきかは販売先の規則も確認する。
6. [製品公開手順](product-launch.md)と[正式テンプレート](product-page-template.md)に従い、サイトの表示と実ストア・配布物の内容を人が確認する。

`scripts/check-release.mjs` は現状、製品ページの URL、メタデータ、Offer、CTA、画像等の構造を検査する。法務リンクを全製品必須にはしない。必要文書が確定した製品についてのみ、存在とリンク先の整合を将来の機械チェックに追加できる。法律上の適否と文言の正確さは人が判断する。

## 自動化できる「要確認」フラグ

将来の検出は、実装の静的調査だけでなく、製品ごとの販売方式・SDK・データフロー申告を入力として使う。検出結果は不足の可能性を示すだけで、違法判定や「適法」認定をしない。

| 検出条件 | 出すフラグ |
| --- | --- |
| Analytics / フォームがあるがデータ説明がない | 利用目的、送信先、プライバシー説明を確認 |
| Cookie / SNS / 動画埋め込みがある | 第三者送信と外部送信規律を確認 |
| crash reporting / telemetry があるが収集フィールドが未記録 | 実データ・既定送信・保持・停止方法を確認 |
| 広告 SDK があるがプライバシー・同意・年齢設定が未確認 | SDK とストア申告を確認 |
| OSS / フォント / 素材 / SDK の同梱があるが権利台帳・notice がない | 再配布・attribution・ライセンスを確認 |
| 有料直接販売だが販売者情報・条件の確認が未完了 | 特商法と申込画面を確認し公開停止 |
| 外部販売先があるが販売主体・返金先が未記録 | ストア方式と返金導線を確認 |
| AI 機能があるが外部送信の記録がない | 入力データ・提供先・保存・ストア申告を確認 |
| Google Play 配布だがポリシー URL / Data safety / 年齢区分がない | Play Console の必須申告を確認 |

## 人間・専門家に残す判断

- **公式情報確認:** 公開時点の消費者庁・個人情報保護委員会・総務省と、利用ストアの規約・年齢・AI・プライバシー要件。
- **専門家確認候補:** 自サイト直接販売、寄付・任意価格の法的位置付け、海外向け販売や越境データ移転、未成年向け・センシティブな内容、サブスク、個人の氏名・住所・電話番号の表示と省略条件。
- **実装・運用確認:** ホスティングログ、実際の SDK 通信、返金を受ける主体、問い合わせメールの処理、ライセンス同梱物、製品とストア表示の一致。
