# 助手A ホームページ制作室

用途・名称・雰囲気・自由な要望から1ページを制作する開発者用の試作です。「サイトを生成」で初稿を作り、「追加指示」で修正します。PCは1,280px、スマホは390pxの幅で表示し、「HTMLを保存」で現在の版を端末に保存できます。購入前の画像確認と、模擬購入後のHTML受け取りも同じPCで試せます。

新規生成・修正では、制作室がサイト名入りのヘッダーとフッターを設置します。本文見出しの短い目次名（任意のdata-nav）を優先し、最初の5つまでにページ内リンクを付け、行き先が2件以上ならヘッダーを追従させます。スマホでは最初の行き先と、フッターの一覧に移動する「目次」を表示します。本文の章立てと見せ方は依頼に合わせて生成します。

最初にジャンルを選び、サイト名を入力します。「載せたいこと」に営業時間や作品名などを書き足せます。メインの色・サブの色は日本語名と色見本から、写真は「おまかせ」「はい（合う素材があれば）」「いいえ」から選べます。希望を省略した場合は制作室が決めます。

## ローカル起動

Node.js 22以降を使用します。専用ウィンドウと確認画像の作成にはリポジトリのルートで `npm ci` を実行し、Playwrightを用意します。Windowsではインストール済みのChromeまたはEdgeを使用できます。他の環境は `npx playwright install chromium` でブラウザを用意するか、`PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` にChromium系ブラウザの実行ファイルを指定します。

**作例を無課金で試す**には `node .studio/server.mjs --examples-only --open` を実行します。ログイン済みの専用ブラウザに制作画面が自動で開きます。喫茶店と音楽公演は実生成の修正版、建築作品集「間庭設計室」は追加条件を使って1回で生成した初稿です。APIキーは不要です。

**自分の依頼でAI生成・修正する**場合は次の手順を使います。「サイトを生成」「修正を反映」を実行するとAPI料金が発生します。有料検証は予算と回数の承認後に実施してください。

1. **リポジトリの外**に、自分だけが読める `studio-secrets.env` を用意します。`OPENAI_API_KEY=…` を設定します。OSからサーバープロセスに環境変数を渡すこともできます。
   通常モードには運営者の非公開制作設定も必要です。既定の場所はリポジトリの親の `studio-design-policy.mjs` です。別の場所に用意する場合は `STUDIO_DESIGN_FILE` にリポジトリ外のファイルのパスを設定してください。運営者が事前に用意した参照画像も公開ディレクトリの外に保管します。サーバーはこのモジュールから制作指示・参照画像・使用素材と表示方法を受け取ります。作例モードは公開チェックアウトのみで利用できます。
2. リポジトリの親にSecretファイルを置いた場合、リポジトリ直下から `node --env-file=../studio-secrets.env .studio/server.mjs --open` を実行します。
3. 自動で開く専用ウィンドウで制作します。起動ごとに発行したログイン情報を、このウィンドウにだけ設定します。最後の制作室タブを閉じるとサーバーも終了します。

普段のブラウザで手動ログインしたい場合は、`--open` を `--session-password` に替えます。端末のURLを開き、ユーザー名 `developer` と表示されたパスワードで認証します。通常モードで固定パスワードを使う場合は、フラグを外し、16文字以上の `STUDIO_PASSWORD` をSecretに設定します。

制作サーバーはループバックで待ち受け、制作画面とすべての `/api/` 操作で開発者を認証します。生成リクエストは制作画面と同じOriginからのJSON POSTに限ります。Cloudflare Pagesの構成と公開サイトの導線を維持しています。`_redirects` で制作室のファイルへのアクセスを404ページに転送します。

## 購入前確認からHTMLの受け取りまで

1. 制作画面で生成・修正したサイト、または保存済みの作例を開きます。必要なら表紙素材を選び、「この版の確認画面を作成」を押します。
2. 「購入者の確認画面」を開き、PC・スマホの画像を切り替えて「この版を確認する」を押します。確認画面にはその版のページ全体を撮ったJPEGが届きます。画像内のリンクや開閉操作は制作画面で検証できます。
3. 制作画面で「状態を更新」を押し、同じ版を選んで模擬購入を確定します。料金は発生しません。
4. 購入者の画面で「納品状況を更新」からHTMLをダウンロードします。写真を含む単一の `index.html` をオフラインで開けます。後から制作画面を修正しても、固定済みの版の内容は変わりません。

固定した版はローカルの使用台帳と同じフォルダー内の `deliveries/` に保存されます。固定済みの版は再起動後も一覧から開けます。固定前の下書きは画面の再読み込みで消えます。作例モードと通常の制作室は別々の保存先を使います。画像の保存上限は1ページの高さ16,000pxです。

確認URLには版ごとのランダムな受け取り用トークンが入ります。同じPCでそのURLを知る人が確認でき、模擬購入確定後はその版を再ダウンロードできます。これは開発用の購入試験です。実際の販売には決済結果と購入者を結び付けた配布、受け取り権限の期限・再発行・取り消しの設計が必要です。

## 生成と記録

Responses APIの `gpt-6-luna` に仕様を送信し、修正時には現在のHTMLと追加指示も送信します。サーバーは依頼に合う制作指示と、構図と素材選びのための非公開の参照画像1枚を同じリクエストでモデルに渡します。参照画像は構図や情報の提示方法を検討するために使い、納品HTMLに組み込む画像は別に管理します。制作設定・参照画像は公開リポジトリの外に保管します。`store: false`、Standard処理で呼び出します。モデルが返したタイトル・HTML本文・CSSを検査して単一のHTMLに組み立てます。プレビューはサンドボックス内で動作し、保存版にもCSPを埋め込みます。

新規・修正の生成時にモデルが依頼の雰囲気に応じて動きの種類と強調する要素を選びます。制作室がCSSを保存HTMLに同梱し、冒頭の登場、対応ブラウザでのスクロールに連動した見出しや作品の表示、ページ内移動、リンクの反応に適用します。明示的な静止希望や端末の動きを減らす設定に対応します。

各生成・修正で、モデルは制作方針と本文を同じ応答内に返します。制作方針は納品HTMLから除きます。生成直後、ローカルのChromiumで完成HTMLを1440・768・390px幅に表示し、ページの横あふれ、ヘッダーのリンク名の切れ、画像とページ内リンクの有効性を調べます。画面には確認結果を表示し、同じ下書きで依頼者が修正を実行した場合に見つかった問題を修正指示に添えます。ブラウザを利用できなかった場合は未確認と表示し、取得済みの下書きを保持します。

制作設定は題材と写真の希望に応じ、表紙と本文の用途に合う素材を最大3点指定します。画像は静的HTMLへWebPで埋め込みます。モデルが省略した選定素材はローカルで補います。従来の3点の同梱作例に加えて写真を収録し、各写真の出典とライセンスを `.studio/art/catalog.json` に記録しています。合う写真がない場合や写真不要の場合は文字や図で構成します。修正リクエストでは画像を短い素材IDに戻すため、前のページのWebPを再送する費用を省きます。新規生成で非公開設定の visualReview がある場合は、PC・スマホの完成画面と生成HTMLを同じモデルに渡し、最大1回自動で仕上げます。通常の非公開設定では、制作前にジャンル名だけで実例をWeb検索（最大1回）し、その観察・依頼文・素材ボードを用いて非公開の制作仕様書を作ります。仕様書は実装と仕上げに引き継ぎます。設定に応じてPC全景・スマホ冒頭・スマホ末尾を別のAPI呼び出しで講評し、指摘を仕上げへ渡します。初稿末尾のfooterがあれば共通の移動リンクをその中に組み込みます。新規生成は最大5回で、検索ツール料金も発生します。実装枠を先に確保し、準備枠が不足する場合は同梱資料で続行します。各API呼び出しを別々に予約・記録し、残り枠不足や仕上げ失敗時は最初の生成版を返します。仕上げ版は3幅の表示検査を通過した場合に採用します。追加指示による修正は1回です。参照画像には画像入力トークンの料金が発生します。

生成後は「表紙素材」で画像を選び直せます。元の図解を含むページでは写真と図解を一緒に確認できます。「AIの構成を使う」を選ぶと生成直後の版に戻ります。表紙選択はブラウザ内の仕上げで、回数枠やAPIクレジットを消費しません。追加指示は元のAI生成版に適用し、制作画面が選択中の表紙を再適用します。HTMLを保存すると現在の仕上がりが1ファイルに入ります。

| 制限 | 1台の制作サーバーでの上限 |
| --- | --- |
| 新規生成と修正の合計 | 6回（失敗も1回） |
| 累計トークン | 240,000（使用量未確定の予約枠を含む） |
| 1回のモデル出力 | 6,000トークン |
| モデルが生成するタイトル・HTML・CSS | UTF-8で48 KiB |
| 画像を埋め込んだ完成HTML | UTF-8で300 KiB |

API送信前に、入力のUTF-8バイト数と構造分の余裕、最大出力を含む枠を予約します。使用量が返ると入力・キャッシュ読み取り・30分/12時間のキャッシュ書き込み・出力・合計の実測値を記録します。書き込み内訳のない旧記録は未計測として集計します。出力検査で失敗しても、報告されたトークンは計上します。通信切断などで使用量が判定できない場合は、その回の予約枠を維持します。自動再試行はありません。

時刻・操作・予約量・成否・トークン数・HTMLバイト数をローカルの `usage.json` に記録します。入力本文、生成HTML、認証情報は含めません。Windowsの保存先は `%LOCALAPPDATA%\joshu-a-studio\usage.json`、他のOSでは `$XDG_STATE_HOME/joshu-a-studio/usage.json`（既定 `~/.local/state/joshu-a-studio/usage.json`）です。再起動後も同じ枠を使います。次の検証枠を用意する場合は、費用の承認後、サーバーを停止し、既存の台帳を保管してから開始してください。

通常の日本語LPは、目次・フッター・空白・閉じた補足を除き、通常表示の本文約1600字を目安に、原稿に応じて代表例・比較・体験の流れを読める本文にします。短い告知は統合し、詳細の開閉は補足に使います。初稿はスマホの冒頭から来訪者が作品や判断材料に触れられる構図を目指します。詳細を開く動きには折り込み・横からの差し込みも選べます。修正では構図変更の指定がある場合を除き、選んだ入口を引き継ぎます。初稿・修正ともアニメーションの量は多めに固定します。端末の動きを減らす設定を尊重します。書体は案件ごとに選定し、見出し・本文・ナビをページ内で統一します。端末にない場合はその案件の代替書体を使います。

無課金で接続境界・保存・使用量処理を検証するコマンドは `node --test .studio/engine.test.mjs .studio/server.test.mjs` です。ブラウザでのページ内移動と確認・納品の操作は `node --test .studio/preview.playwright.test.mjs .studio/delivery.playwright.test.mjs .studio/brief.playwright.test.mjs` で確認できます。システムのChromium系ブラウザを使う場合は、その実行ファイルを `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` に指定します。モデル単価は[OpenAIのモデル仕様](https://developers.openai.com/api/docs/models/gpt-6-luna)を参照してください。

表紙画像の共通寸法は既定値です。生成したCSSで構図に合わせて上書きできます。共通ナビとフッターの地色・文字色は --studio-paper と --studio-ink で指定できます。

### デザイン10選

認証済みの制作室から10業種の完成作例を閲覧できます。通常モードで作例を選ぶと、そのHTML・CSSと表紙画像を生成の参考にします。依頼のジャンル、メインカラー、サブカラーは独立した設定です。未選択時は従来どおりおまかせです。
## 生成原稿のローカル再検査

HTML・CSSの検査に失敗した生成原稿は、利用記録と同じディレクトリの `recovery/` にJSONで保存します。通常起動のWindows環境では `%LOCALAPPDATA%\joshu-a-studio\recovery` です。エラー表示のファイル名で対象を特定できます。HTML断片の行・列はJSON内の `site.html` を展開した本文上の位置です。単純な英数字の属性値は許可済み属性と値の検査後に引用符付きへ整形します。

開発者はJSONのコピーで `site.html` または `site.css` を修正し、リポジトリ直下から `node .studio/recover.mjs <修正したJSON> <新規HTMLファイル>` を実行できます。保存時と同じ素材処理とHTML/CSS検査を通った場合だけ新規HTMLを出力します。API呼び出しは発生しません。JSONは開発用の非公開原稿として扱います。
